# 機能要件

- ユーザーはtwitterにemailでサインアップできる
- emailはunique
- ユーザーはサインアップ後に以下の項目を登録する
  - ユーザー名(例: @tomoya_yoshida)(uniqueであること)
  - 電場番号(unique)
  - 名前(表示名)
  - 自己紹介
  - 場所
  - ウェブサイト
  - 生年月日
  - プロフィール画像
  - アバター画像
- ユーザーは140文字のツイートできること
- ユーザーはツイートにいいねできる
- ツイートをリツイートできる
- ユーザーは他のユーザーをフォローをできる
- ユーザーは他のユーザーにダイレクトメッセージを送信することができる
- いいね、フォローをされると通知を受け取ることができる
- ツイートをブックマークすることができる

# Twitterデータモデリングの際にやるべきこと

データベース設計において、やるべきことリストをまとめる

- データの抽出
  - 機能要件からデータを抜き出してみる
  - 実際のアプリやWebサイトをみるなどしてサーバから取得していそうなデータを抜き出してみる
- エンティティの定義
  - 抜き出したデータをもとにエンティティ（概念もしくは実体）を定義する
- ER図の作成
  - エンティティの関連性をER図に落とし込む
- テーブルの定義
  - ER図をもとにテーブルの定義を行う

## データの抽出

実際のTwitter（X）画面を見てどんなデータをデータベースから取得していそうか挙げてみる

- モノ　※めったに更新されないマスターデータに該当
  - ユーザープロフィール
    - ユーザーID（@lokusukeなど）
    - パスワード（ハッシュ値）
    - 名前（表示名）
    - 電話番号
    - メールアドレス
    - 場所
    - Webサイト
    - 生年月日
    - プロフィール画像URL
    - アバター画像URL
    - 自己紹介文
    - アカウント解約日

- 出来事（イベント） ※増え続けるトランザクションデータに該当
  - ユーザープロフィール
    - フォローする
    - ブロックする
    - ダイレクトメッセージを送る
  - Twitterタイムライン
    - ツイートする(140文字制限)
    - いいねする
    - リプライする
    - リツイートする
    - ブックマークする
    - 通知を受ける

## エンティティの定義

### マスターデータ（更新頻度が低い）

- Users
  - 登録ユーザプロファイルというモノの集合体
    - 複数のユーザプロファイルが登録されている

### トランザクションデータ（頻繁に更新される）

- follows
  - フォローの集合体
    - AさんがBさんをフォローするという事実の集合体
    - フォローするユーザはユーザIDに存在していないとおかしい
- blocks
  - ブロックの集合体
    - AさんがBさんをブロックするという事実の集合体
    - フォローするユーザはユーザIDに存在していないとおかしい
- tweets
  - ユーザがツイートするという事実の集合体
    - 複数のユーザが投稿したツイートの内容が登録されている
- replies
  - ツイートに対してリプライするという事実の集合体
- Likes
  - ユーザーがツイートに対していいねするという事実の集合体
- comments
  - ユーザーがツイートに対してリプライするという事実の集合体
- retweets
  - ユーザーがツイートに対してリツイートするという事実の集合体
- bookmarks
  - ユーザーがツイートに対してブックマークするという事実の集合体
